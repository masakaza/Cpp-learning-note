# 06 · 模板

模板让函数或类可以针对多种类型复用实现。模板不是运行时的“万能类型容器”；编译器会在使用到具体模板参数时生成相应的实例化代码。

## 1. 函数模板

```cpp
template <typename T>
T larger(T a, T b) {
    return a < b ? b : a;
}
```

`typename` 和 `class` 在模板类型参数声明中通常等价。调用时编译器会尝试从实参推导模板参数；也可以显式指定，例如 `larger<int>(1, 2)`。推导规则并非所有情况下都能自动满足，混合类型时可能需要显式转换或指定模板参数。

## 2. 模板重载与匹配

函数模板可以与普通函数、其他函数模板重载。调用时会进行候选函数和最佳匹配的选择；普通函数并不在任何情况下都无条件优先。应通过小型示例观察具体重载决议，避免只凭一句口诀推断。

## 3. 类模板

```cpp
template <typename T>
class Box {
public:
    explicit Box(const T& value) : value_(value) {}
    const T& get() const { return value_; }
private:
    T value_;
};
```

使用类模板时通常要提供模板实参，如 `Box<int> box(42);`。类模板成员函数也可以在类外定义，但定义前需要写模板参数列表，并在限定名中使用 `Box<T>`。

## 4. 为什么模板实现通常放在头文件

普通函数可以只在头文件中声明、在 `.cpp` 中定义，再由链接器连接。但模板实例化需要编译器看到相应定义；如果定义隐藏在另一个 `.cpp` 文件中，使用方可能无法生成需要的具体实例。因此模板实现常放在 `.h` / `.hpp` 中，或采用显式实例化等更进阶的组织方式。

`.hpp` 只是常见命名约定，不是语言强制规则；关键在于编译器在实例化点是否能看到模板定义。

## 5. 模板参数类型的要求

模板中的类型必须支持实际用到的操作。例如代码里执行 `a < b`，传入的类型就必须能进行相应比较；代码里执行 `std::cout << value`，类型需要支持流插入。模板并不会自动让任意类型都具备这些能力。
