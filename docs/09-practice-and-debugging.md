# 09 · 编译、调试与学习习惯

## 1. 一次只编译一个示例

学习目录中的示例通常各自带有 `main()`，适合独立编译，而不是把所有源文件一起构建。示例：

```bash
g++ -std=c++17 -Wall -Wextra -pedantic "code/核心/引用/引用的基本使用.cpp" -o demo
./demo
```

如果程序依赖同目录的 `.cpp` 或头文件，需要一起编译，例如：

```bash
g++ -std=c++17 -Wall -Wextra -pedantic   "code/基础/函数/函数模块文件调用.cpp"   "code/基础/函数/swap.cpp" -o demo
```

具体依赖关系以文件内容为准。Windows 上可以使用 MinGW-w64、Visual Studio 或其他 C++ 工具链，命令形式会有所不同。

## 2. 阅读错误信息

建议按以下顺序定位：
1. 找第一条真正的编译错误，而不是只看最后一条；
2. 检查报错行附近的分号、括号、类型和变量名；
3. 检查声明与定义是否一致；
4. 检查头文件是否包含、模板定义是否可见；
5. 如果是链接错误，检查相关 `.cpp` 是否参与构建；
6. 修改后用最小示例复现并验证。

## 3. 学习代码时值得额外检查的地方

- 指针是否初始化、是否可能越界或悬空；
- `new` / `delete` 是否配对，有无重复释放和内存泄漏；
- 拷贝构造和赋值操作是否符合资源所有权语义；
- 容器迭代器是否因插入、删除或扩容而失效；
- 文件是否成功打开，读写是否成功；
- 线程是否正确 `join`，共享数据是否存在数据竞争；
- 输入是否可能失败，循环是否有可靠退出条件。

## 4. 建议的代码迭代方式

保留原始练习作为学习轨迹；需要修正时，可以在注释中记录问题，或建立 `examples-improved/` 目录放入修正版。这样能区分“当时怎么理解”与“现在推荐怎么写”，也更容易比较进步。

## 5. GitHub 协作建议

- 每完成一个主题，提交一次有意义的 commit，例如 `docs: add vector notes`。
- 新增代码时同时补充索引和对应文档。
- 不要把编译产物、IDE 临时文件、个人绝对路径或密钥提交到仓库。
- 合并他人改动前，至少编译其新增或修改的示例。
